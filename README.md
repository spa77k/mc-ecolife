# EcoLifeAssist（エコライフアシスト）

PaperMC サーバー向けの、プレイヤーの継続的なログインとコミュニティ活性化を支援するプラグインです。
**カレンダー式ログインボーナス**、**友達招待システム**、**Discord通知連携**、**画像ポスター**の機能を提供します。
一般プレイヤー向けの主要機能をまとめた、右クリックで開く **スマホ** も配布します。
（デイリー任務や実績など、毎日のプレイ動機につながる機能も今後順次追加予定です）

## 主な機能

### スマホ

ログイン時にスマホを1個配布します。右クリックすると、オークションを中心に、売り買い・移動・職業・記録・案内を選べます。`/phone` でも開け、紛失時は `/phone get` で再受取できます。Java版・統合版の専用テクスチャと運用方法は [スマホのガイド](docs/phone.md) を参照してください。

### 画像ポスター

運営が登録したPNG・JPEGを `/poster` の一覧から選び、地図一式を受け取って額縁に飾れます。1×1〜4×4ブロックに対応し、再起動後も表示を復元します。画像追加要望は既存のフィードバックで受け付けます。登録方法・権限・保存データは [ポスターの運営ガイド](docs/posters.md) を参照してください。

### ログインボーナス（カレンダー式）

サーバーに参加してから3秒後に、その日の報酬が**自動で**インベントリへ付与されます（コマンドを入力する必要はありません）。

#### カレンダーの進み方
報酬表は1マス目〜31マス目まで用意されており、月の後半ほど価値の高い報酬が配置されています。

- **受け取り回数で進行**: その月に受け取った回数に応じてマスが進みます（1回目＝1マス目、2回目＝2マス目）。
- **休んでも後退しない（累積式）**: ログインしなかった日があっても現在のマスが戻ることはありません。ただし進みもしないため、休んだ日数分だけ月末の高ランク報酬マスには届かなくなります。
- **月替わりでリセット**: 月が変わると全員1マス目に戻り、前月の進行状況は引き継がれません。
- **皆勤賞**: その月の日数分を毎日欠かさず受け取ったプレイヤーのみが、最終マスに到達できます。
  - 2月は最大28マス目（閏年は29マス目）、31日ある月のみ31マス目に届きます。

#### 報酬のバランス設計
- **前半マス**: パン・松明・石炭・鉄・矢など、「その日の作業や冒険がはかどる消耗品」を中心に設定されています。
- **後半マス（21マス目以降）**: 毎日継続してログインしたプレイヤーへのご褒美として、ダイヤモンド等の貴重品を配置しています。
- **経済バランスの維持**: Jobs Reborn の時給相場（駆け出しプレイヤーで約1,000S）や QuickShop の市場相場を壊さない配分を意識しています。
- すべての報酬内容は `config.yml` の `rewards` でマスごとにカスタマイズ可能です。
- **14マス目**はAdminShop製の「帰還の護符」1個です。以前の経験値の瓶16個と石炭ブロック2個から差し替えました。護符はAdminShopの効果データ付きで、最後の死亡地点へ戻る使い切りアイテムです。AdminShopが停止中・未導入、または商品が未登録の場合、報酬と受け取り記録を保留し、復旧後に `/daily` で受け取れます。

#### 持ち物がいっぱいのとき
インベントリに空きがない場合は、入り切らなかったアイテムが**プレイヤーの足元にドロップ**されます。ログイン直後に自動配布する仕組み上、持ち物が満杯の状態で参加するケースを想定した仕様で、ドロップ時にはその旨がチャットで通知されます。

#### 1日の区切り（リセット時刻）
- 日付および月の切り替わりは、**日本時間の毎朝4:00**（`config.yml` の `day.timezone: "Asia/Tokyo"` / `day.reset-hour: 4`）を基準に判定されます。
- 深夜0時ではなく朝4時としているのは、日付をまたいで遊んでいるプレイヤーの受け取り判定がセッション中に切り替わってしまうのを防ぐためです。
- 日付変更時刻をまたいで遊び続けているプレイヤーには、1分ごとの定期巡回チェックによってその日のボーナスが自動付与されます。

#### 連続ログイン日数と累計ログイン日数
カレンダーの進行マスとは別に、プレイヤーの活動記録として2つの指標を表示・管理しています。

```text
9月のカレンダー: 5 / 30 マス          ← 今月の報酬マスがどこまで進んだか
これまでの記録: 連続 15日 / 累計 15日   ← これまでの参加実績（報酬内容とは無関係）
```

- **連続ログイン日数**: 前日から途切れることなく連続してログインボーナスを受け取っている日数（1日でも空くと1日にリセット）。
- **累計ログイン日数**: これまでにボーナスを受け取った通算日数。
- **最長連続日数**: 現在の連続日数が自己ベストに届いていない場合のみ、「`最長は 15日でした。`」のように過去の最高記録が表示されます。

> [!NOTE]
> **マスは月が変わると1マス目に戻りますが、連続ログイン日数は月をまたいでも継続します。**
> そのため、「連続35日／今月2マス目」のような状態になるのは正常な動作です（役割が異なる指標のため行を分けて表示しています）。
> なお、経済インフレを防ぐため連続ログイン日数に応じた追加報酬は設けておらず、報酬内容はカレンダーのマス目のみに基づいて決定されます。
> カウント対象は「ログインボーナスを受け取った日」です（`ecolife.daily` 権限がない場合や `login-bonus.enabled` を `false` にしていた期間はカウントされません）。

### 友達招待システム

新規プレイヤーが紹介者を登録し、一定時間プレイすることで双方に通貨報酬が付与される仕組みです。

#### 基本ルールと報酬
- **報酬額**: 紹介者に **2,000S** / 新規プレイヤーに **1,000S**（Vault経済連携）
- **連携**: 時間判定には公開API対応版のMcLevelが必要です。最後の操作から1分後の放置時間は含みません。McLevelを利用できない場合は登録・支払いを保留します。
- **達成条件**: 新規プレイヤーの累計アクティブプレイ時間が **2時間**（McLevelの7,200秒）に到達すること。
- **プレイヤーの利用手順**:
  1. 紹介者が自身のプレイヤー名を友達に伝えます（紹介者は機能導入後に一度ログインしておく必要があります）。
  2. 初参加の友達が、累計アクティブプレイ時間2時間未満のうちに `/invite <紹介者の名前>` を実行して紹介者を登録します。
  3. 累計アクティブプレイ時間2時間に達すると、オンライン中の定期確認（約10秒ごと）により自動で双方へ報酬が支払われます（紹介者はオフラインでも受取可能です）。
- **GUIとランキング**:
  - `/invite`: チェストGUIを開き、自身の招待コード、招待履歴・状況、自分が受けた招待、ランキングを確認できます。
  - `/invite top`: 招待成立数の上位10人をチャットに表示します。

#### 不正防止と設計
- **IP制限なし**: 同一IPや接続情報の有無に関係なく招待登録・報酬成立が可能です。旧版で同一IPのため保留された招待も、次回のオンライン判定で再開します。自分自身への招待・循環招待の禁止とアクティブ時間条件は継続します。
- **決済の安全性**: Vaultの支払い処理において、例外やサーバー停止が起きても二重払いが発生しないよう、ステータス遷移（`PENDING` → `SENDING` → `PAID`）をSQLiteへ同期コミットしながら管理しています。

詳細な仕様やコマンド、障害復旧手順については [友達招待の運営ガイド](docs/invite.md) を参照してください。

### Discord通知連携

依頼板（ContractBoard）やオークション（AuctionHouse）など、サーバー内の別プラグインで発生した出来事を Discord Webhook へ自動通知します。

#### 疎結合・動的イベント購読設計
EcoLifeAssist は発生元プラグインを**コンパイル時依存にしていません**。
Bukkitのカスタムイベント（`getNotifyKind()` および `getNotifyPlaceholders()`）を `Class.forName` と動的イベント購読で検知します。
これにより、特定のプラグインが導入されていない環境でもエラーにならず単体で安全に起動でき、新しい通知元プラグインを追加する際も EcoLifeAssist 側のコードを変更することなく `config.yml` への設定追記のみで対応可能です。

#### 既定の通知種別
- `contract-created`: 依頼板（mc-irai）に新しい依頼が投稿されたとき
- `auction-listed`: オークション（mc-auction）に新しい出品があったとき

#### 設定方法
`config.yml` の `notify:` セクションで設定します。

1. `enabled: true` に設定します。
2. `webhook-url` に Discord の Webhook URL を入力します（`${CFG_ECOLIFE_DISCORD_WEBHOOK}` のような環境変数の自動置換形式にも対応しています）。
3. サーバーコンソールまたはゲーム内で `/ecolife reload` を実行して設定を反映します。

#### 通知頻度の制御（レート制限）と安全対策
- **レート制限（間引き）**:
  - `min-interval-seconds`: 通知種別ごとの最短送信間隔
  - `per-player-cooldown-seconds`: 同一プレイヤーによる連投抑制クールダウン
  - `max-per-minute`: サーバー全体の毎分送信上限（Discordのレート制限対策）
  - 上限を超えた通知は破棄され、破棄された件数が1分に1回以下の頻度でログに記録されます。
- **プレイヤー入力のサニタイズ（無害化）**:
  - 依頼タイトルやアイテム名などの自由入力文字列は、Discord送信前に自動整形されます（カラーコードの除去、`allowed_mentions` による `@everyone`/`@here` の無効化、Markdown記号のエスケープ、改行除去、`text-max-length` による文字数制限）。

#### 通知が届かない場合の確認手順
通知が飛ばない場合は、以下の順序で状態を確認してください：

1. `notify.enabled` が `true` になっているか。
2. `notify.webhook-url` が実際のURLに置き換わっているか（空欄や未置換の `${...}` のままでは送信されません）。
3. `/ecolife notify status` を実行し、対象の発生元が「購読中」になっているか確認します。
   - **未導入**: 発生元プラグイン（ContractBoard / AuctionHouse など）がこのサーバーに入っていません。
   - **型が不正 / 型が不正のため停止**: イベントクラスが通知規約を満たしていません。
4. 間引き設定（`min-interval-seconds` / `per-player-cooldown-seconds` / `max-per-minute`）で破棄されていないか、`/ecolife notify status` の破棄件数およびサーバーログを確認します。

> [!TIP]
> `/ecolife notify test` コマンドを実行すると、間引き設定を無視してテスト通知を即座に1件送信できます。

| コマンド | エイリアス | 権限 | 既定 | 説明 |

| `/daily` | `/bonus`, `/loginbonus` | `ecolife.daily` | 全員 | 今月の進み具合と次のマスの中身を確認します。未受取分がある場合はその場で付与されます。 |
| `/phone` | — | `ecolife.phone` | 全員 | スマホのメニューを開きます。`/phone get` で再受取できます。 |
| `/invite <紹介者名>` | `/invite code <紹介者名>` | `ecolife.invite` | 全員 | アクティブプレイ時間2時間未満で紹介者を登録します。 |

| `/invite top` | — | `ecolife.invite` | 全員 | 友達招待の成立数ランキング（上位10名）をチャットに表示します。 |

| コマンド | 権限 | 既定 | 説明 |
| --- | --- | --- | --- |

| `/ecolife reset <プレイヤー名>` | `ecolife.admin` | OP | 指定プレイヤーのログインボーナス記録を初期化します（次回受取時は今月の1マス目から）。 |

| `/invite admin info <新規>` | `ecolife.admin` | OP | 指定した新規プレイヤーの招待状態、紹介者、支払い状況、IP救済状況を確認します。 |

## 保存データ

データは `plugins/EcoLifeAssist/` 配下に保存されます。

### `data.yml`（ログインボーナス記録）
プレイヤーごとの「いま数えている月」「その月に受け取った回数」「最終受け取り日」「通算回数」「皆勤した月数」「連続日数」「最長連続日数」「連続の起点」を保存します。
- **非同期書き込み**: 受け取りのたびに非同期でディスクへ保存し、サーバー停止時にも確実に書き切ります。
- **`streak-day` と `last-claim` の分離**: 連続日数の判定には `last-claim`（最終受け取り日）ではなく `streak-day`（連続を最後に伸ばした日）を使用します。これは、過去のログイン記録から遡って連続日数を付与した場合に、`last-claim` を起点にすると初回の受け取りで連続が1にリセットされてしまうのを防ぐためです。
- **後方互換性**: `streak` などの項目を持たない古い `data.yml` もそのまま読み込み可能です。存在しない項目は `0` として扱われ、次回の受け取りから集計を開始します（読み込み時の警告も出ません）。

### `invites.db`（友達招待記録・SQLite）
プレイヤー情報、IPハッシュ履歴、招待・支払い状態、登録時報酬額、登録・成立時刻、管理操作の監査ログなどを保存します。
- データの整合性とトランザクション管理のため SQLite（WALモード）を使用しています。
- バックアップはサーバー停止中に行うか、SQLiteバックアップAPIを使用してください（稼働中にDBファイルのみをコピーするとWALの確定済み内容を取りこぼす場合があります）。

## ビルドとテスト

### ビルド
Maven を使用してパッケージングします（Java 25 が必要です）：

```sh
mvn -B package
```

### ローカル検証
- **プラグイン起動テスト**:
  ```sh
  ./scripts/test-plugin.sh
  ```
  ローカルのPaperサーバーを起動し、プラグインが正常に有効化されることおよび `/ecolife reload` が動作することを確認します（実行には `server-data/` に Paper の JAR が必要です）。アイテム受取や演出の確認は、起動後にクライアントから `localhost:25568` へ接続して行ってください。

- **友達招待の自動テスト**:
  ```sh
  python3 scripts/test-invite-paper.py
  ```
  Paper隔離サーバー（`target/invite-paper-smoke`）上で、実コマンド・イベント・GUI生成を駆動し、通常の報酬入金、2時間境界、同一IPの登録・報酬成立と旧IP保留の再開、改名対応、二重払い防止、片側失敗と手動復旧、Vault未導入時の起動などを検証します。
